# Version 1 (CS-540 ACPS, IIT Ropar, Jan–May 2024): what was wrong, and how v2 fixes it

This folder keeps the original course submission unchanged: notebooks, report, write-up and checkpoint slides. A later review of the code found that **the v1 results do not measure crop-type classification**, so the numbers in `report_2024.pdf` (accuracy 89–97 %, F1 92–97 %) should not be quoted. The rewritten pipeline in [`cropclf/`](../cropclf) fixes every point below.

| # | Issue in v1 | Where | Effect | Fix in v2 |
|---|---|---|---|---|
| 1 | **Wrong target.** `y = data.iloc[:, -1]` is TimeSen2Crop's *pixel-condition flag* (0 clear, 1 cloud, 2 shadow, 3 snow), and the output layer is `Dense(4)`. | all model notebooks | The models learned to recognise clouds, shadows and snow, not crops. One model per crop folder was trained on that 4-class flag problem. | The label is the crop folder (16 classes). The flag is used only to **mask** bad observations. `data.py` |
| 2 | **No time series.** Each CSV *row* (one acquisition date) was a separate sample of 9 band values. The Conv1D and LSTM layers ran across the 9 *bands*, not across time. | all model notebooks | Temporal models never saw the temporal dimension, which is the whole point of the dataset. | Each pixel becomes a 12-month × 9-band series (monthly median of clear observations), as in the dataset paper. `data.py` |
| 3 | **Test and validation leakage.** For validation and test, `process_folder(...)` built a *new* model and called `model.fit` on that same split before scoring it (TempCNN, Transformer). | `TempCNN.ipynb`, `Transformer.ipynb` | The reported validation and test scores are fit-to-the-same-data scores, not generalisation. | Train on train tiles → select the epoch on the validation tile → score the test tile once. `train.py` |
| 4 | **Untrained model at test time.** In the LSTM notebooks the test branch calls `model.evaluate` on a freshly initialised model. | `weighted_lstm/crop*.ipynb` | The notebooks' own outputs show **test accuracy between 0.5 % and 69 % and macro-F1 between 0.004 and 0.32** across the 16 crop notebooks. The report's 92.8–96.4 % LSTM figures come from training curves instead. | Same protocol as above. |
| 5 | **"Transformer" without attention over a sequence.** Dense layers plus one `Attention()([x, x])` on a single feature vector. | `Transformer.ipynb` | Self-attention over a length-1 input does nothing useful. | A real Transformer encoder over the 12 monthly tokens with positional encoding. `models.py` |
| 6 | **Per-file normalisation.** A new `StandardScaler` was fit on every CSV, including validation and test files. | all model notebooks | Removes the absolute reflectance level that separates crops, and leaks test statistics. | One normaliser fit on the training tiles, reused for validation and test. `Normalizer` |
| 7 | **"Weighted LSTM" mostly unweighted.** Class weights appear in some notebooks but were computed over the 4 flag classes. | `weighted_lstm/` | Not the class-imbalance weighting of the benchmark. | Class-weighted cross-entropy over the 16 crop classes, computed on train. |
| 8 | **NDVI health labels.** NDVI < 0 was labelled "dead crop" and 0–0.33 "unhealthy crop". | NDVI notebooks | Negative NDVI means water, snow or cloud. Low NDVI is normal for bare soil before sowing and after harvest, not a sign of disease. | Vegetation-density classes (bare/sparse/moderate/dense), median phenology curves, clear observations only. `ndvi.py` |
| 9 | **Hard-coded server paths** (`/workspace/awadh/...`) and 16 copy-pasted notebooks. | everywhere | Not reproducible. | One package with a CLI, tests and CI. |

## Reference point

The dataset authors report test-tile overall accuracies of **81.7 % (TempCNN), 83.4 % (LSTM), 84.4 % (Transformer) and 85.4 % (weighted LSTM)** using 12 monthly composites (Weikmann, Paris & Bruzzone, *IEEE JSTARS* 14, 2021). Results well above that range on the spatially independent test tile would themselves be a warning sign.
